# ClaimsGuru Domain Migration Guide
## Transitioning to Subdomain: `health.waferwire.com`

**Target Subdomain:** `health.waferwire.com`  
**Current Domain:** `wct-health.com` / `www.wct-health.com`  
**Target Environment:** Microsoft Azure Pre-Production / Production (`claimsGuru` Resource Group)  
**Document Location:** Project Root Directory (`DOMAIN_MIGRATION_GUIDE_HEALTH_WAFERWIRE.md`)  

---

## 1. Overview & Objective
This guide outlines the step-by-step procedure to migrate the ClaimsGuru platform from `wct-health.com` to your official corporate company subdomain: **`health.waferwire.com`**.

The migration spans four distinct layers:
1. **DNS Registrar Records** (for `waferwire.com`)
2. **Azure Container Apps Custom Domain & Free SSL Binding** (`cg-preprod-cin-frontend`)
3. **Microsoft Entra External ID Authentication Redirects** (preventing login errors)
4. **Backend CORS & Frontend Codebase Canonical Links**

---

## 2. Step 1: DNS Records Configuration (for `waferwire.com`)

Log in to the DNS management portal for **`waferwire.com`** (e.g., GoDaddy, Cloudflare, AWS Route53, Namecheap, etc.) and add the following two DNS records:

| Record Type | Host / Name | Target / Value | TTL | Purpose |
|---|---|---|---|---|
| **CNAME** | `health` | `cg-preprod-cin-frontend.centralindia.azurecontainerapps.io` *(or your frontend default FQDN)* | 300s / Auto | Routes all web traffic for `health.waferwire.com` to the Azure Container App. |
| **TXT** | `asuid.health` | *[Verification Code generated by Azure]* | 300s / Auto | Proves domain ownership to Azure before SSL issuance. |

> **Note on Value:** You will retrieve the exact TXT verification string from the Azure Portal during Step 2.

---

## 3. Step 2: Bind Custom Domain & SSL in Azure Container Apps

1. Open the **Azure Portal** and navigate to:
   * **Resource Groups** -> **`claimsGuru`**
   * Select Container App: **`cg-preprod-cin-frontend`**
2. In the left navigation menu under **Settings**, click **Custom domains**.
3. Click **+ Add custom domain**:
   * **Domain:** `health.waferwire.com`
   * **Hostname type:** Azure-managed certificate
   * Copy the TXT verification code if not already placed in DNS (Host: `asuid.health`).
   * Click **Validate**.
4. Once validation status shows green checkmarks for both DNS resolution and ownership:
   * Select **Certificate type:** **Azure-managed certificate** (Azure generates and automatically renews a free TLS/SSL certificate).
   * Click **Add / Bind**.
5. Once completed, `https://health.waferwire.com` is live with valid HTTPS.

---

## 4. Step 3: Update Microsoft Entra External ID (Authentication)

> ⚠️ **CRITICAL STEP:** If this step is skipped, users attempting to log in on `health.waferwire.com` will receive error:  
> `AADSTS50011: The reply URL specified in the request does not match the reply URLs configured for the application`.

1. In the Azure Portal, switch to your Entra External ID tenant:
   * **Tenant:** `claimsguruapp.onmicrosoft.com`
2. Navigate to **Microsoft Entra ID** -> **App registrations**.
3. Select the ClaimsGuru client application.
4. Under **Manage** in the left menu, click **Authentication**:
5. Under **Single-page application (SPA)** / **Web**:
   * Click **Add URI** and add:
     * `https://health.waferwire.com`
     * `https://health.waferwire.com/auth/callback`
   * Under **Front-channel logout URL** / **Post-logout redirect URIs**:
     * Add `https://health.waferwire.com`
6. Click **Save** at the top.

## 5. Step 4: Backend API CORS Update

To ensure the browser allows API calls from `health.waferwire.com` to the backend Ingress API (`cg-preprod-cin-ingress`):

* In [`services/ingress/app/main.py`](file:///c:/Project/claimsguru/services/ingress/app/main.py), add `https://health.waferwire.com` to the list of allowed CORS origins:
  ```python
  allowed_origins = [
      "https://health.waferwire.com",
      "https://www.wct-health.com",
      "https://wct-health.com",
      # ... other origins
  ]
  ```

## 6. Step 5: Frontend Codebase Updates

The following files in `ui/web/` contain domain logic to be updated:

1. **Authentication Helper ([`ui/web/lib/auth.ts`](file:///c:/Project/claimsguru/ui/web/lib/auth.ts)):**
   Update domain canonicalization:
   ```typescript
   if (dynamicOrigin.includes('wct-health.com') || dynamicOrigin.includes('waferwire.com')) {
     dynamicOrigin = 'https://health.waferwire.com';
   }
   ```
2. **API Client ([`ui/web/lib/api-client.ts`](file:///c:/Project/claimsguru/ui/web/lib/api-client.ts)):**
   Add `waferwire.com` to custom domain routing:
   ```typescript
   if (host.includes('wct-health.com') || host.includes('waferwire.com') || host.includes('claimsguru')) {
     // Route API requests through the custom domain proxy
   }
   ```
3. **Next.js Middleware ([`ui/web/middleware.ts`](file:///c:/Project/claimsguru/ui/web/middleware.ts)):**
   Ensure `health.waferwire.com` is treated as a primary subdomain and not redirected to `www.wct-health.com`.
4. **Company & Legal Links:**
   * [`ui/web/app/privacy&policy/page.tsx`](file:///c:/Project/claimsguru/ui/web/app/privacy&policy/page.tsx)
   * [`ui/web/app/delete-account/page.tsx`](file:///c:/Project/claimsguru/ui/web/app/delete-account/page.tsx)
   * [`services/ingress/app/privacy_policy.py`](file:///c:/Project/claimsguru/services/ingress/app/privacy_policy.py)
   Update operational and contact links to `health.waferwire.com`.
